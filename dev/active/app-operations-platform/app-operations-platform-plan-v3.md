# 앱 운영 플랫폼 개발계획 v3 — 데모와 실제 운영 통합

고정일: 2026-09-11. [v2](app-operations-platform-plan-v2.md)와 [v1](app-operations-platform-plan.md)의 전체 요구사항을 승계한다. 원본 계획은 보존한다.

사용자 추가 요구: 실제 계정을 연결했다고 가정하여 모든 기능과 화면을 구현한다. 실제 계정 연결 후 같은 앱을 바로 사용할 수 있어야 한다.

## 추가 완료 기준

- R-13: 9개 연결, 다섯 엔진의 프로젝트와 관리 데이터가 포함된 영속 데모 공간. 실제/데모 분리, 모드 표시, 초기화, 인증·네트워크·심사 실패 재현.
- R-14: 대시보드·프로젝트·배포/심사/자료·마케팅·수익화·커뮤니티·키·운영/복구·이력 화면에서 입력→처리→상태·결과 확인을 수행한다. 출시 파이프라인은 검수부터 업로드와 공지까지 연결한다.
- R-15: 실제 연결 모드도 같은 작업 계약을 사용한다. 공식 API로 가능한 미구현 스토어·광고·SNS 경로를 추가한다. 플랫폼이 요구하는 최초 등록·권한·동의는 준비 상태와 후속 동작으로 명시한다.

## Phase 12 — 데모·실제 운영 통합

1. T-12.1 공통 실행 계약과 모드별 독립 저장공간·데모 어댑터 구현. 실서비스 네트워크와 데이터가 섞이지 않는지 검사.
2. T-12.2 모든 관리 화면과 대시보드·출시 파이프라인·운영 준비 화면 구현. 실제 브라우저로 주요 사용자 흐름 검증.
3. T-12.3 남은 공식 스토어 자료·심사 및 마케팅·SNS 동작 연결. 모의 HTTP로 요청·오류·재실행 계약 검사.
4. T-12.4 운영 설정·준비 진단·백업/복구와 전체 이력 통합. 작업 중 충돌·잘못된 입력·복구 검사.
5. T-12.5 전체 테스트·타입·패키지·독립 리뷰, 브라우저 기능 검증 후 지원표와 증거 갱신.

전체 계획의 실계정·실기기·OS 검증을 데모 성공으로 대체하지 않는다. 이번 요청에서 계정 부재는 구현을 중단할 이유가 아니다. 실행 상세는 [공통 실행 계약](../../../docs/demo-execution-contract.md), 진행은 [tasks](app-operations-platform-tasks.md)·[context](app-operations-platform-context.md)에 기록한다.
