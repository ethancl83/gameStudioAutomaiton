# 앱 운영 플랫폼 개발계획 v4 — 설치 후 운영 준비 완성

고정일: 2026-09-11. 사용자 추가 지시: “완전준비단계까지 만들어”. [v3](app-operations-platform-plan-v3.md)와 승계한 v1·v2를 보존한다.

## 목표와 판정

프로젝트별로 계정·앱 매핑·엔진·SDK·빌드 격리·서명·배포 권한·게임 내 연동·상시 실행의 실제 준비 상태를 확인하고 부족한 소프트웨어 설정을 앱에서 설치·연결·복구한다. 하나의 도구나 계정이 있다고 전체를 준비됨으로 표시하지 않는다. 사용자 제공 장비·라이선스·계정의 최초 인증/동의는 저장해 재사용한다.

데모는 준비 과정 전체를 같은 화면에서 체험한다. 실제 작업은 확인된 자원과 권한을 사용한다. SDK 적용은 원본 보존·변경 미리보기·충돌 검사·복구를 갖추고, 게임별 보상/구매 이벤트 미연결 상태를 성공으로 숨기지 않는다. 실계정·macOS/Windows 실기기·30일 운영 증거를 생성했다고 주장하지 않는다.

## Phase 13 — 완전 준비 구현

1. T-13.1 프로젝트별 준비 진단·실행 전 점검·최초 설정 마법사·영속 진행 상태.
2. T-13.2 검증된 엔진/SDK 설치·기존 도구 탐지·설치 재개/실패 복구·라이선스 필수 단계 연결.
3. T-13.3 macOS/Windows 빌드 격리 실행·취소·호스트 접근 차단·플랫폼별 서명/러너 준비.
4. T-13.4 광고/결제 SDK 탐지·의존성/코드 적용·설정·게임 이벤트 연결·검증·되돌리기.
5. T-13.5 네이티브 기동·앱 종료 후 제어 서비스·OS 로그인 자동 시작·배포/업데이트 경로.
6. T-13.6 전체 데이터/산출물·암호화 자격 증명 이전 백업·무결성 검사·재시작 복구.
7. T-13.7 남은 스토어 미디어·앱 매핑·수익/광고 운영의 실제 경로와 준비 조건 보완.
8. T-13.8 자동·실제 도구·브라우저·네이티브 패키지·독립 리뷰와 운영 준비 수용 검사.

## 실행과 검증

root가 위험도가 높은 설치·격리·자격 증명/백업·최종 통합을 수행한다. 실제 Opus·Grok 워커는 독립 파일 범위의 수명주기·SDK 구현을 병렬 담당하고 Sol/Opus 리뷰 세션으로 재검토한다. 같은 파일을 동시에 편집하지 않는다. 구현 후 API와 UI 소비자를 함께 연결한다.

확정된 외부 API/OS 계약은 설치 버전과 공식 문서로 확인한다. 실제로 실행 가능한 환경에서 정상·취소·오류·재시작·권한 경계를 검증한다. 도구·장비가 없는 검증은 실행 증거와 구별해 기록하고 독립적으로 가능한 구현을 계속한다.

진행·수정 파일·명령·잔여 조건은 [tasks](app-operations-platform-tasks.md)·[context](app-operations-platform-context.md), 검증 결과는 [검증 기록](../../../docs/verification.md)에 갱신한다. 이전 고정 계획은 직접 수정하지 않는다.
