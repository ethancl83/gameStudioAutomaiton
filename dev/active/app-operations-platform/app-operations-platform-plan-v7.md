# 앱 운영 플랫폼 개발계획 v7 — 요청 기반 AI와 이어지는 대화

고정일: 2026-09-13. v1–v6는 이력으로 보존하며 v7을 현재 기준으로 한다.

## 확정 요구

- 프로젝트 등록·화면 진입·앱 재시작으로 AI를 실행하지 않는다. 사람이 채팅을 전송하거나 각 화면의 **AI 요청** 버튼을 눌러야 실행한다.
- 버튼은 화면별 기본 작업과 현재 선택한 프로젝트/계정을 전달한다. 사용자가 같은 정보를 채팅에 다시 입력하지 않는다. 요청과 응답은 채팅에 남긴다.
- Codex / OpenCode **CLI**만 지원한다. 기존 로그인과 모델 설정을 사용하고 두 실행기에 같은 앱 MCP 도구를 제공한다.
- 프로젝트별 대화와 전체 운영 대화를 보관한다. 실제 CLI 세션 ID와 제공자를 저장하고 매 요청에서 정확한 ID로 resume한다. 화면 이동·완료·오류·재시작으로 새 세션을 만들지 않는다. 제공자는 클리어 전 고정한다.
- 클리어는 현재 AI를 중지하고 늦은 응답을 차단한 뒤 대화와 CLI 세션 연결을 초기화한다. 다음 요청만 새 세션에서 실행한다. 이미지·스토어 자료·외부 작업 이력은 보존한다. CLI가 원래 보관하는 이력 파일의 삭제를 뜻하지 않는다.
- 등록을 요청하면 프로젝트 자료를 분석하고 스토어 문구와 실제 이미지 파일을 준비해 등록 작업을 진행한다. 찾거나 생성할 수 있는 값을 다시 요구하지 않는다. 로그인·본인 확인·계약·알 수 없는 사실·부족한 실행 도구만 알린다.
- 기존 Electron과 제어 서비스·암호화 보관함·큐·외부 변경 기록을 재사용한다. 원본 프로젝트 수정·빌드·심사 제출·공개·광고 집행·SNS 전송은 이번 실행 범위에 포함하지 않는다.
- 2차 마케팅 실험·수익률 개선·커뮤니티 자동관리는 [별도 기획](../ai-growth-operations/ai-growth-operations-plan-v2.md)으로만 남긴다. 해당 화면의 버튼은 저장된 데이터 분석과 초안까지 수행한다.

## 구현 순서와 완료 조건

1. CLI 어댑터: JSONL 세션 ID/assistant 응답, 명시적 resume, 프로세스 취소와 오류. ID 누락·변경 때 임의 새 세션 금지.
2. 영속 세션: 요청만 실행, provider 고정, 중복 실행 차단, 재시작 보존, clear 실행 정리와 응답 격리.
3. 요청된 등록 도구: 프로젝트 읽기·문구/이미지·기존 계정 재사용·공식 콘솔 경로·스토어 API 연결. 생성 그림과 실제 스크린샷 구별. 큐의 중복 방지와 결과 불명 계약 준수.
4. 화면: 공통 AI 요청/대화, 화면의 실제 선택을 전달, 대화 전송·중지·클리어·제공자 선택·자료 확인. 등록과 이동으로 실행 0건.
5. 검증: 실제 HTTP/MCP·임시 DB·CLI 대역 프로세스로 정상/실패/clear 경합/resume를 검사. 타입·전체 검사·빌드, 네이티브/화면 기능과 시각 검사를 수행하고 실서비스 미검증을 구분한다.
