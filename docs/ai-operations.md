# AI 요청과 대화

**AI 요청**과 **AI 대화**는 현재 화면·선택 대상을 전달해 기존 채팅을 연다. 버튼 클릭만으로 AI를 실행하거나 고정 작업을 사용자 발언으로 저장하지 않는다. 사용자가 채팅에 작성한 내용을 **전송**하거나 Enter를 눌러야 실행한다. 프로젝트 등록·화면 이동·새로고침·재시작만으로도 실행하지 않는다.

버튼에 들어 있던 계정 설정·스토어 등록 등의 기본 지시는 제거했다. 서버는 내용 없는 요청을 거부한다. 새로운 작업 후보나 요청 흐름은 추가하지 않았으며, 요청 방식의 재설계는 사용자가 별도로 정한다.

대상 프로젝트는 화면에서 선택한 항목을 그대로 사용한다. 대상이 없는 화면은 전체 운영 대화로 연결된다. 전송할 때의 화면·선택 대상이 전달되므로 이전 화면에서 고른 계정이 다른 화면의 요청에 남지 않는다. AI 운영 화면에서는 대화 대상을 선택할 수 있다. 여러 프로젝트 중 하나를 임의로 골라 스토어에 쓰지 않는다.

## Codex / OpenCode CLI

설치된 `codex`와 `opencode`를 탐지하며 API 키 입력 폼을 추가하지 않는다. 각 CLI에 이미 설정한 로그인·모델을 재사용한다. AI 선택의 자동 모드는 **제공자 선택**이며 자동 작업 시작을 의미하지 않는다.

프로젝트별 대화와 전체 운영 대화는 별도로 보관한다. 첫 요청에서 받은 실제 CLI 세션 ID를 저장하며 후속 요청은 `codex exec resume <id>` 또는 `opencode run --session <id>`로 이어진다. 화면을 닫거나 앱을 재시작해도 같은 ID를 사용한다. 진행 도중 종료됐으면 다음 사용자 요청을 기다린다.

클리어 전에는 제공자를 바꾸지 않는다. 세션 ID를 잃거나 resume에 실패해도 조용히 새 대화를 만들지 않는다. **클리어**는 현재 실행을 정리한 뒤 대화와 세션 연결을 비운다. 다음 요청에서 새 세션을 시작하며 제공자를 다시 선택할 수 있다. 클리어 자체는 AI를 실행하지 않는다. 준비한 문구·이미지와 외부 변경 이력은 보존하며, CLI 자체가 보관하는 과거 세션 파일을 삭제하는 기능은 아니다.

## 설치된 CLI와 MCP 연결 진단

저장소 루트에서 `node --import tsx scripts/verify-agent-cli.ts`를 실행하면 앱이 탐지하는 Codex/OpenCode의 버전과 신규·재개 명령의 도움말 수락을 확인한다. 기존 MCP 브리지도 실제 자식 프로세스로 기동해 초기화, 도구 목록, 로컬 읽기 응답과 시험 서버의 쓰기 거부 전달을 검사한다.

이 명령은 모델 작업을 요청하지 않는 기본 진단이다. 로그인 상태, 실제 모델 응답, 이미지·브라우저 도구와 스토어 반영은 검증하지 않는다. 도움말 검사는 실제 세션 생성·재개가 성공했다는 증거가 아니며, 그 동작의 자동 회귀 검사는 CLI 대역을 사용하는 `tests/project-agent.test.ts`에서 별도로 수행한다. Codex의 비대화형 실행·재개 계약은 [공식 문서](https://learn.chatgpt.com/docs/non-interactive-mode)를 참고한다.

결과는 `tmp/agent-cli-20260922/report.json`에 저장된다. CLI 누락·명령 거부·MCP 오류는 실패 종료 코드로 알린다. 앱의 탐지 순서는 일반 셸의 `PATH` 순서와 다를 수 있으므로 보고서의 실행 파일 경로와 버전을 확인한다.

## 자료 준비와 계정 연결

AI는 제한된 프로젝트 자료와 기존 계정·앱 매핑·작업 결과를 읽는다. 문구에는 분석 근거를 남긴다. 등록할 이미지가 없으면 정적 SVG를 작성해 실제 PNG로 렌더링할 수 있다. 전역 CLI 이미지 플러그인은 격리 실행에 상속하지 않는다. 생성한 홍보 그림을 실제 게임 스크린샷으로 표시하지 않는다.

스토어 API 변경은 기존 큐·정책·중복 방지를 통과한다. 현재 문구 반영, 준비한 이미지 업로드와 앱 확인 근거가 있어야 등록 완료로 표시한다. 신규 앱 생성이 API로 지원되지 않으면 사용자가 공식 콘솔에서 생성한 뒤 앱 매핑을 연결해야 한다. 브라우저 도구 부재, 로그인·MFA·CAPTCHA, 계약 동의나 자료에서 알 수 없는 필수 사실은 대화에서 정확히 요청한다.

원본 프로젝트 수정·빌드, 심사 제출·실제 공개, 광고비 집행, SNS 발송은 이번 AI 실행 범위에 포함하지 않는다. [2차 성장 운영 기획](../dev/active/ai-growth-operations/ai-growth-operations-plan-v2.md)은 별도 문서이며 주기적 실험·고객응대 기능은 아직 구현하지 않았다.

## 앱 내부 AI 설정과 개발 작업 (2026-09-24)

설정의 **앱 내부 AI**에서 Codex/OpenCode 설치·로그인·연결 검사와 기본 모델을 선택한다. 분석·구현·리뷰·운영별로 별도 선택할 수도 있다. 모델 목록에서 고르면 직접 입력할 필요가 없으며, 빈 모델은 해당 CLI 기본값을 따른다. 로그인 동의·MFA는 공급자가 여는 브라우저/CLI에서 진행한다. 설정 변경은 새 작업에 적용되고 진행 중인 작업의 공급자·모델은 유지된다.

**개발 작업**에서 프로젝트를 선택하면 Git remote를 감지한다. GitHub CLI 로그인 후 저장소 목록에서 연결하거나 폴더를 골라 clone한다. Git 탭에서 변경·diff·stage/unstage·커밋·브랜치·fetch·fast-forward pull·승인 push를 수행한다.

이슈/PR의 **가져와서 분석**은 별도 worktree와 고유 브랜치를 만들고 원본·댓글·리뷰·CI 자료를 `dev/active/github-<종류>-<번호>/`에 저장한다. 터미널이 열리고 선택한 CLI가 plan/context/tasks를 만든다. 구현 실행 후 별도 리뷰와 프로젝트 검증을 거쳐 변경을 확인한다. 터미널 닫기는 화면 분리이며, 다시 열면 같은 세션에 연결한다. 실행 중지는 작업을 취소한다. 앱 종료 시 앱이 소유한 세션을 정리한다.

커밋·푸시·PR은 각각 화면의 승인 버튼 또는 프로젝트별 자동화 설정을 따른다. 기본값은 수동이다. 자동 커밋은 검증한 파일·명령과 현재 상태가 같아야 가능하며 검증 정의 변경은 수동 확인으로 보류한다. 푸시는 해당 작업 커밋 SHA만 반영한다. 응답이 유실되면 **원격 반영 확인**으로 조회하며 자동으로 재전송하지 않는다. PR의 이슈 닫기 문구는 병합 시 효력이 생기며, 푸시만으로 이슈 해결 완료라고 표시하지 않는다. fork/출처 불명 PR은 분석·구현·검증까지 제공하고 원본 저장소로 커밋·푸시하는 작업은 제한한다.

CLI 실행은 macOS/Linux 파일·네트워크 격리 안에서 수행한다. AI에는 배포·GitHub 인증과 호스트 Keychain을 제공하지 않는다. 기존 CLI 인증을 작업 전용 폴더로 복사하고 전역 MCP·플러그인·훅은 상속하지 않는다. 기존 앱 대화는 앱 전용 MCP만 사용한다. OpenCode 세션을 이전할 때는 해당 native 세션만 CLI export/import로 옮긴다. 터미널의 알려진 인증값을 마스킹하며 백업에서 CLI 인증·Git 메타데이터·의존성 폴더를 제외한다. 복원한 개발 작업은 문서와 소스를 읽기 전용으로 보존한다. 원본 프로젝트를 다시 연결하고 새로 가져와 작업한다.

## 웹 프로젝트 배포

**웹 배포**는 앱에서 관리하는 웹 프로젝트를 Netlify/Vercel에 배포하는 화면이다. CLI 브라우저 로그인 → 프로젝트 연결 → 준비 상태 확인 → Preview 또는 Production 승인 순서다. CLI가 제공하는 선택 화면으로 계정·팀·프로젝트를 연결한다. 화면에 표시된 커밋이 바뀌면 재확인해야 한다.

Vercel은 커밋한 소스 스냅샷을 업로드해 클라우드에서 빌드한다. Netlify는 `package-lock.json` 기반 격리 빌드 후 정적 결과만 업로드한다. Vite/Astro 출력은 `dist`, 빌드 없는 사이트는 `public`을 자동 선택하며 명백한 정적 사이트만 루트 업로드를 허용한다. 소스·문서가 섞인 루트는 `public`으로 공개 파일을 분리해야 한다. Next.js 서버 빌드는 Vercel 또는 Netlify Git 연동을 사용한다.

서비스 완료 상태와 실제 URL의 HTTP 응답을 모두 확인해야 성공으로 표시한다. 접근 보호·리디렉션·응답 유실은 확인 필요 상태로 남긴다. 서비스에서 직접 결과를 확인했으면 이력의 재배포 잠금 해제를 승인할 수 있다. 이 동작은 성공 판정을 대신하지 않는다. 개발 작업의 **자동 Preview 확인**은 Git 연동 배포를 조회하며 별도 배포를 중복 요청하지 않는다.

현재 macOS 앱·tmux/PTY·격리를 검증했다. Linux는 tmux/bubblewrap/socat이 필요하며 이번 변경의 Linux 실기 수용은 별도다. Windows의 AI 개발 작업 실행은 지원하지 않는다. 서명·공증된 앱 배포와 실계정 OAuth 신규 동의·GitHub push/PR·Netlify/Vercel 실제 업로드는 이번 검증에 포함하지 않았다.
