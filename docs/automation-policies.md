# 자동화 정책

Last Updated: 2026-09-12

SNS의 일일 한도를 기존 예약 수보다 낮추면 확정·미확정 외부 효과를 먼저 계산하고, 아직 전송하지 않은 예약에는 DB의 생성 순서를 적용한다. 서로 다른 채널이 동시에 실행돼도 오래된 예약이 먼저 한도를 배정받는다. 이미 전송한 작업은 새 예약과 구분해 상태 확인을 마친다. 공급자가 종결 실패를 확인한 작업은 이후 게시 한도에서 제외한다.

[작업 목록](../dev/active/app-operations-platform/app-operations-platform-tasks.md) · [실행 계약](workflow-contract.md)

프로젝트마다 자동 빌드·배포, 허용 연결, 광고/수익화 변경 허용, 일일 설정 예산 한도·통화를 저장한다. 기본 자동 변경은 꺼져 있고 저장한 범위 안의 반복 작업에는 재승인을 요구하지 않는다. 예약과 실제 외부 쓰기 직전에 정책을 다시 검사한다.

- 소스 감시: 30초 주기 파일 경로·크기·수정 시각 검사, 두 번 관찰/최소 20초 안정화 후 빌드. 최초 등록은 기준값을 잡고 비밀·캐시·링크는 제외한다. 내용 해시 감시는 후속 보완이다.
- 빌드: 지원 타깃과 마지막으로 저장한 타깃별 설정 사용. 도구·서명·라이선스·격리 부재는 실패 원인으로 표시한다.
- 업로드: 배포 정책을 켠 이후의 새 성공 빌드만 타깃/서비스를 매칭해 내부 시험 트랙으로 예약한다. 저장한 결정 키로 재시작 중복을 막는다.
- 동기화: 정상 연결 1시간, 회복 상태 1분 간격이며 작업 중복을 피한다. 권한 철회 시 해당 계정만 복구한다.
- 처리 추적: 외부 처리 대기 업로드를 1분마다 재조회한다. 재전송과 구분한다.
- 예산: 프로젝트에 매핑된 모든 계정의 기존·중지 캠페인과 대기 변경을 합산한다. 통화를 임의 환산하지 않고, 한도 초과 상태에서도 기존 캠페인 중지는 허용한다.

설정 예산은 공급자가 청구하는 특정 날짜의 실제 지출 상한을 보장하지 않는다. 외부 콘솔 동시 편집과 보고 지연을 완전히 차단하지 못한다. 실시간 지출 차단·성과 기반 재배분·미출시 앱 광고 대기·소재 자동 제작은 미구현이다.

제어 서비스 실행 중 감시·예약이 동작한다. OS 서비스 설치·자동 업데이트·장비 이전은 후속 작업이다.

## SNS·커뮤니티 정책

커뮤니티 화면에서 프로젝트별 채널·일일 게시/답글 한도(1~100)·출시 공지 문구·자동 답글 규칙을 저장한다. 켜진 정책 안에서 반복 실행하며 매번 승인을 묻지 않는다. 예약은 SQLite에 저장하고 채널별 실행 ID를 연결한다. 재시작/부분 예약 뒤에는 같은 멱등 키를 사용하며 이미 전송한 작업을 재게시하지 않는다. 미전송 예약만 취소할 수 있다.

일일 한도는 UTC 기준 완료 게시와 현재 대기·미확정 쓰기를 프로젝트 전체 채널에 걸쳐 합산한다. 실행 직전에도 최신 정책을 재확인한다. 공개 production/public/default 배포가 확인된 뒤에만 출시 공지를 만들며 내부 시험 업로드는 제외한다. 최초 정책을 켜기 전의 과거 출시/댓글에는 자동으로 소급 실행하지 않는다.

자동 답글은 저장한 문구를 대소문자 구분 없이 포함하는 새 멘션·답글에 고정 답변을 한 번 보낸다. 수신 내용이 운영 정책을 바꾸거나 명령을 실행하지 않는다. 자신의 글, 잘못된 시각, 프로젝트를 유일하게 확인할 수 없는 글은 자동 답글 대상이 아니다. Threads는 공식 소유 여부 필드를 사용한다.

X/Threads는 주기적인 sync로 글·멘션/답글을 수집한다. Steam은 연결 정책에서 공개 뉴스를 주기적으로 읽으며 공지 발행은 미지원이다. Threads 컨테이너 발행 결과는 읽기로 확인하고, X 응답 유실처럼 결과를 증명할 수 없는 경우는 이력의 조치 대기로 남긴다. [소셜 연동](social-operations.md) · [기능표](integration-capabilities.md).

## 앱별 동기화와 공개 공지

등록된 스토어 앱은 `sync-app`으로 프로젝트별 조회한다. 연결의 계정 보고서 `sync`는 한 번 예약한다. 정상 앱 조회는 1시간 간격, 최근 24시간 내 출시 작업이 있으면 1분 간격이다. 첫 공개 목록은 과거 버전 기준선으로 저장하며 공지하지 않는다. 이후 Play production의 PUBLISHED, Apple READY_FOR_SALE/READY_FOR_DISTRIBUTION, Steam live:public/default 전환을 앱·버전·스토어별로 한 번 공지한다. 업로드 이력의 성공 상태만으로는 공지하지 않는다. 초기 내부 트랙 조회를 공개 기준선으로 오인하지 않는다.
