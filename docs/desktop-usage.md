# 데스크톱 앱 사용 안내

Last Updated: 2026-09-11

이 문서는 데스크톱 화면(`apps/desktop`)의 사용 흐름과 보안 경계를 설명한다. 기준 계약은 [구현 계약](implementation-contract.md)과 `packages/domain/index.ts`이며, 화면은 제어 서비스의 실제 API를 소비한다. 실제 제어 서비스·브라우저의 데모 흐름은 검증했고, 실서비스 계정·다른 OS 검증은 남아 있다. [검증 기록](verification.md)에서 수행 범위를 확인한다.

## 실행

- 개발(브라우저 미리보기): `npm run dev`는 제어 서비스와 Vite dev 서버(`http://127.0.0.1:5173`, 포트는 `APPOPS_DEV_PORT`로 변경)**만** 띄운다(Electron은 실행하지 않는다). 이어서 **같은 데이터 폴더**에서 `npm run preview`를 실행하면 1회용 미리보기 토큰이 담긴 URL이 시스템 브라우저(인증된 세션)로 열린다. 토큰은 URL 프래그먼트로 한 번만 전달되고 화면이 소비한 뒤 즉시 지운다. 이후 이 브라우저의 `/api` 요청은 사용자 전용 미리보기 쿠키가 있어야 통과하며(없으면 401), 프록시가 bearer를 주입해 제어 서비스(`127.0.0.1:4317`, `APPOPS_PORT`)로 전달한다. 화면은 논리 경로(`/state` 등)를 호출하고 transport가 `/api`를 1회 붙인다.
- 개발(데스크톱): `APPOPS_DEV_SERVER_URL`이 지정되면 Electron이 그 dev 서버를 로드한다. **loopback(127.0.0.1/localhost/::1) 주소만 허용**하며, 그 외 주소는 무시하고 컴파일된 화면을 로드한다. Electron은 IPC로 접근하므로 미리보기 쿠키나 브라우저 로그인이 필요 없다.
- 프로덕션(패키지): `npm run build` 후 `npm run desktop`(`electron .`) — Electron main(`dist/apps/desktop/electron/main.js`)이 렌더러(`dist/apps/desktop/renderer/index.html`, 상대 경로 자산)를 로드한다. 컨트롤러가 떠 있지 않으면 main이 `ELECTRON_RUN_AS_NODE=1`로 컨트롤러를 기동하고 `controller.json`과 `/health`를 기다린다.

기본 첫 화면은 **대시보드**다. 모든 값은 제어 서비스의 `/state`(모드에 따라 `/api/...` 또는 `/api/demo/...`)에서 온 것이며 화면이 임의로 만들지 않는다. 연결 전에는 “연결하는 중” 상태를 표시하고, 실패 시 오류·다시 시도를 제공한다.

## 실행 모드: 데모와 실제

같은 화면·요청·작업 계약으로 **데모**와 **실제** 운영을 모두 쓴다. 기본값은 데모 미리보기다.

- **모드 표시·전환**: 머리말에 현재 모드(데모/실제) 표식과 전환 컨트롤이 항상 보인다. **실행 모드 권한은 네이티브(Electron)에서 main 프로세스가 소유·영속한다** — renderer의 `localStorage`가 아니라 사용자 데이터 디렉터리의 `desktop-mode.json`(0600)에 보관하며, 없거나 손상되면 안전 기본값 `demo`다. renderer 문자열로는 권한을 바꿀 수 없다.
  - **실제(live) 전환은 main 소유의 단 하나의 확인창**을 통과해야만 반영된다(취소하면 아무 것도 바뀌지 않는다). 네이티브에서는 renderer 확인창을 두지 않는다(이중 프롬프트·재로그인 없음). **데모로의 전환은 파괴적이지 않으므로 추가 확인 없이** 즉시 반영한다.
  - **브라우저 미리보기 폴백**은 기존 UX 그대로다 — renderer 확인창 + 선호를 브라우저 저장소(`appops.runtime.mode`, 기본 `demo`)에 보존한다.
- **경로 분리**: ApiClient는 데모 모드에서 모든 데이터 요청의 논리 경로 앞에 `/demo`를 한 번 붙인다(예: `/state` → `/api/demo/state`). 실제 모드는 동일한 논리 경로를 접두 없이 쓴다(`/api/state`). 데모 초기화·시나리오는 항상 `/demo` 접두를 쓴다.
- **네임스페이스 결속(main 강제)**: 네이티브에서 **모든 특권 변경(수명주기·자동 시작)·파일 브리지(백업 저장/가져오기)·일반 요청 라우팅은 main 소유의 실행 모드에 결속**된다. main은 요청 경로의 네임스페이스(`/demo` 대 실제)가 자신의 실행 모드와 **정확히 일치**할 때만 전달하고, 어긋나면 거부한다(`mode_mismatch`). 손상된 renderer가 데모 세션에서 실제 경로를(또는 그 반대) 밀어 넣어도 라우팅되지 않는다(fail-closed). 데모 차단(`demo_blocked`)도 renderer가 넘긴 문자열이 아니라 main 소유 모드로만 판정한다.
- **불변 모드 경계(강한 격리)**: ApiClient 인스턴스의 실행 모드는 **불변**이다. 네이티브에서는 어떤 데이터 요청/디스패치보다 먼저 `bootstrap()`이 **main 소유의 권한 모드를 받아 1회 확정**한 뒤 화면을 마운트한다(권위 있는 비동기 부트스트랩). 브라우저에서는 생성 시 저장소 값을 읽어 고정한다. 확정 이후 이 인스턴스로 만든 모든 요청·콜백·pending promise(폴더 선택 등)는 그 모드만 대상으로 삼는다. **전환은 (네이티브는 main 확인창을 거쳐) 페이지를 전체 새로고침(`location.reload`)** 하여 새 인스턴스를 만든다. 이전 인스턴스의 타이머·pending 요청·콜백은 모두 폐기되므로, 늦게 도착한 응답이 새 트리로 들어가거나(stale) 다른 모드에 쓰기를 보내는 일이 원천적으로 불가능하다. 새로고침 후 뷰는 기본 화면(대시보드)에서 다시 시작한다.
- **데모 성격**: 데모는 시드된 9개 연결·5개 엔진 프로젝트·정책·상품·캠페인·게시물·지표·키 메타데이터를 별도 저장공간에서 제공한다. 작업은 데모 저장공간에 기록되고 외부 공급자에 전송되지 않는다. 각 화면에 데모 표식을 두고, 결과의 성공 표시를 실제 공급자의 성공으로 주장하지 않는다.
- **실제 성격**: 실제 모드는 연결된 실제 계정과 저장된 권한·정책·검증된 빌드만 사용한다. 데모의 실행·자원을 실제 계정으로 복사하지 않는다.
- **검증 범위**: `/demo` 라우팅·독립 저장공간·운영·출시·데모 제어는 구현 및 실제 제어 서비스·브라우저 검증을 완료했다. Electron IPC 허용 경로는 자동 검사로 확인했다. 이 Linux 호스트의 네이티브 창 기동은 chrome-sandbox/AppArmor 제약으로 막혔으며, 패키지에 포함된 Electron Node 제어 서비스는 기동·출시·백업 검사를 통과했다.

## 화면

### 대시보드
- 초기 화면. 프로젝트·연결·진행 중 작업·출시 파이프라인·활성 캠페인 수를 통계 타일로, 출시 파이프라인·최근 활동·수익 개요(통화별)·스토어 출시 현황·최근 작업을 조밀하게 개괄한다.
- **활성 캠페인**은 전체가 아니라 실제 집행 중(활성/serving)인 캠페인만 센다(일시중지·종료·삭제·초안·반려 제외).
- 수익 개요는 각 통화별로 **기여이익·수익·광고비 라벨을 값과 함께** 표시한다(값만 보여주지 않는다).
- 각 카드에서 해당 화면으로 이동한다. 값이 없는 지표는 0이 아니라 **미수집**으로 표시한다. 데모에서는 하단에 데모 안내를 표시한다.
- 일별 상세(수익/광고비 차트·표)는 수익화 화면의 **일별 수익·광고비**에서 본다.

### 운영 준비
설치 후 실제 운영까지 필요한 준비를 한 화면(`SetupView`)에서 다룬다. 데모·실제 모두 같은 논리 API(`/setup`, `/projects/:id/preparation`, `/projects/:id/store-app`, `/projects/:id/integration`)를 쓰며, 모드 경계는 다른 화면과 동일하다(불변 클라이언트).

- **개요**: 실행 모드, 대상별 준비 완료 수, 빌드 격리(백엔드/사유)를 요약한다. 값은 `GET /setup`의 `PreparationState`에서 온다.
- **엔진·SDK 준비**: 검증된 공식 카탈로그(Godot·템플릿·Android SDK 등)를 내려받아 설치하거나, 이미 설치한 도구의 **절대 경로**를 연결한다. 폴더형 도구는 폴더 선택(데스크톱) 또는 경로 입력, 실행 파일형 도구는 경로 입력으로 등록한다. 설치는 실시간 진행률·취소·실패 표시를 제공하고, 라이선스가 있는 도구(Android SDK·JDK 등)는 **설치당 1회** 동의 후에만 설치한다. 저장 경로는 신뢰 호스트 입력이며 시스템 환경 변수를 바꾸지 않는다. `다시 검사`로 도구를 재탐지한다.
- **프로젝트 준비**: 프로젝트·**배포 대상**을 선택하면 대상별 준비 점검(`준비됨/설정 필요/차단됨`)과 항목별 상세를 보여 준다. 각 점검의 조치는 기존 화면(프로젝트·계정 연결·환경·정책의 빌드 키·운영·복구의 러너)으로 이동하거나 공식 안내 링크를 연다. 준비 설정(빌드 러너·배포 계정·엔진 실행 파일·내보내기 프리셋/Xcode scheme·SDK 연동 필요 여부)을 저장한다.
- **스토어 앱 매핑**: 프로젝트를 스토어의 실제 앱과 연결한다(Google Play=패키지 이름, App Store·Steam=숫자 ID). 저장하면 해당 계정이 프로젝트 정책의 허용 연결에 부여된다. **저장만으로 ‘확인됨’이 되지 않는다** — 연결 확인은 실제 읽기 전용 조회(데모는 시뮬레이션)에 성공해야만 `확인됨`으로 표시한다. 폼 저장에서 검증을 추정하지 않는다.
- **게임 내 광고·결제 연동**: 프로젝트의 엔진·기존 SDK를 탐지하고, 공급자(AdMob·AppLovin MAX·Play 결제·App Store 결제)·플랫폼·계정·(공개)앱 ID와 **동기화된 광고 단위/상품**을 선택해 미리보기를 만든다. 선택 항목은 저장된 `ExternalResource.id`이며 임의 경로·비밀이 아니다(MAX SDK 키는 런타임 바인딩이라 입력하지 않는다). 목록은 이 프로젝트·선택 계정에 속한 자원만 노출한다. 미리보기는 **계획된 파일 변경(경로·이유·해시)**·의존성 카탈로그(아티팩트·버전·출처)·연결(wiring) 상태·발견 사항을 원본 변경 없이 보여 준다. 적용은 코드·의존성을 **설치·연결(wired)**하며, 이는 게임 실행 중 이벤트가 동작하는 **런타임 검증과 구분**된다(‘런타임 검증’ 체크박스는 없다). 적용 이력에서 되돌리기를 제공한다.
- **앱·제어 서비스 수명주기**: 제어 서비스는 화면(창)과 **독립** 실행된다. 앱(창)을 닫아도 인가된 자동화는 계속 실행되며, 중지·재시작은 **명시적 조치**다. 이 제어는 HTTP가 아닌 **IPC로 동작**하므로 제어 서비스가 내려가 HTTP(`/state`)가 끊겨도 상태 조회·재시작을 쓸 수 있다(중지 후에도 화면이 `중지됨`과 IPC 재시작 버튼을 제공). 로그인 자동 시작(사용자별)을 켜고 끌 수 있으나, 안정된 설치 경로가 아니면 켜기를 막는다. 안정 경로 판정은 경로 문자열 패턴이 아니라 **설치된 앱(`app.isPackaged`) 또는 통합된 AppImage(`APPIMAGE`)** 여부로 하므로 Windows 임시/언팩 경로와 정상 설치 경로의 `release` 세그먼트 오탐을 함께 피한다. **데모 모드에서는 실제 제어 서비스나 OS 자동 시작을 절대 바꾸지 않는다** — 이 불변식은 UI 계층뿐 아니라 **main 프로세스 경계에서도 강제**한다(변경 IPC는 **main이 소유한 실행 모드**로 판정해 데모면 거부한다. renderer가 모드 문자열을 넘기지 않으며, 권한은 `desktop-mode.json`에 영속된 main 소유 값이 정한다). 상태 조회는 데모에서도 읽기 전용으로 허용한다. **브라우저 미리보기에서는 데스크톱 전용 제어임을 안내하고 조작을 노출하지 않는다**(브라우저에서 시스템 명령을 실행하지 않는다). Linux 네이티브 샌드박스 준비가 필요하면(chrome-sandbox/AppArmor) 경고와 함께 안내만 표시한다.
  - **명시적 중지의 내구성**: 명시적 중지는 자식 프로세스 정리로 인해 강제 종료(SIGKILL 승격)로 번지더라도 서비스 매니저(systemd `Restart=on-failure` 등)의 자동 재기동으로 되살아나지 않는다. 중지 시 데이터 폴더에 내구성 있는 중지 표식(`controller.stop`)을 남기고, 제어 서비스 진입점·헤드리스 기동 경로가 이 표식을 보면 기동을 건너뛴다. 명시적 시작(앱 재실행·다시 시작 버튼·`node scripts/launch.mjs --force`)만 표식을 지운다. systemd 유닛은 추가 안전장치로 `SuccessExitStatus=SIGKILL`을 명시한다.
  - **자동 시작 아티팩트 인코딩**: systemd `Environment=`·Desktop Entry `env` 접두·schtasks `set` 값은 공백·따옴표·`%` 필드 코드·개행을 안전하게 인코딩하거나 위험 값(제어문자·cmd 메타문자·`/TR` 상한 초과)을 거부한다(지시문 주입·공백 경로 파손 방지). systemd·Desktop Entry 인코딩은 이 Linux 호스트에서 렌더 출력으로 검증했고, **schtasks(Windows)·LaunchAgent(macOS)의 실제 등록·상태·기동은 정적 구현만 확인**했으며 해당 OS 런타임 증거는 없다. schtasks 상태 조회는 `/FO LIST /V`의 `Scheduled Task State`를 파싱해 **비활성(Disabled) 작업을 ‘켜짐’으로 표시하지 않는다**(정적 검토). `scripts/launch.mjs`의 헬스 확인은 유한 시간 안에 공개 `/api/health`(startedAt 일치)와 인증된 `/api/state`(bearer 수락)를 함께 검사한다.

### 프로젝트
- 목록 표는 좁은 폭에서 보조 열(앱 식별자·마지막 검수)을 숨기고 **동작(열기) 열을 오른쪽에 고정**해, 어떤 폭에서도 열기 버튼이 잘리지 않는다. 행 전체도 클릭하면 상세로 열린다.
- **데모 프로젝트 등록**: 데모 모드에서는 폴더 경로 없이 **엔진 샘플 선택기**(Godot·Unity·Unreal·네이티브 Android·네이티브 iOS)로 등록한다. 선택하면 제어 서비스가 `/demo/<engine>` 경로의 basename으로 합성 프로젝트를 만들어 탐지·검수·빌드·출시 흐름을 실제와 동일하게 보여준다(실제 파일 미접근). 실제 모드에서는 기존대로 폴더 경로를 입력·선택한다.
- **빌드 러너 선택**: 빌드·출시 폼에서 준비된 원격 러너(`GET /operations`의 `ready` 러너)를 선택할 수 있다. 비우면 현재 OS에서 로컬 빌드한다. 러너 프로토콜은 플랫폼을 구분하지만, 현재 내장 격리 실행은 Linux만 구현·검증됐다. macOS/Windows 러너의 실기기 지원은 [지원표](build-support.md)를 확인한다.
- 폴더를 등록하면 엔진·버전·타깃·앱 식별자를 탐지한다(읽기 전용, 원본 미수정).
- 검수 탭: 심각도·위치·수정 방법을 표시. 오류가 있으면 배포 빌드 전에 확인한다.
- 빌드 탭: 타깃·구성·엔진 실행 파일·(Godot)프리셋·(iOS)scheme을 지정해 빌드를 시작하고, 로그·취소·재시도를 제공한다. 필요한 엔진·도구가 없으면 성공으로 처리하지 않고 무엇을 준비해야 하는지 오류로 안내한다. 취소는 원본 프로젝트를 건드리지 않으며 감사 로그·스냅샷 등 이력은 보존한다.
- 실행 정책 탭: 자동 빌드/배포, 캠페인·수익화 쓰기 허용, 일일 예산 한도·통화, 허용 연결을 저장한다. 저장 범위 안의 반복 작업은 매번 확인하지 않는다.
- 빌드 보안 탭: 이 프로젝트의 **Android 서명 키스토어**를 선택하고, 빌드 전에 가져올 **SSH 빌드 의존성**(SSH 키·`ssh://` 저장소 URL·브랜치/태그 리비전·스냅샷 하위 배치 경로, 예: `addons/private_sdk`)을 추가한다. 배치 경로는 상대 경로만 허용하며 절대 경로·상위(`..`) 이탈은 막는다. SSH 의존성은 빌드 **전** 안전하게 내려받아 스냅샷에 배치되고, Android 키는 빌드 **후** 결과물 서명에 쓰인다. 자격 증명 자체는 여기서 다루지 않고 환경·정책의 빌드 키에서 1회 등록해 재사용한다.

### 계정 연결
계정은 최초 한 번 연결하면 여러 프로젝트에서 재사용한다. 정상 갱신·재시작에는 다시 로그인하지 않는다.

- **데모 연결**: 데모 모드에서는 시드된 9개 연결이 이미 있고, 연결 추가는 **자격 증명 입력 없이** 공급자·이름·식별자만 받는다(제어 서비스가 합성 계정 생성). 조치가 필요한 데모 연결은 **복구 시도**(= 상태 검사)로 자격 증명 없이 복구하며, OAuth·자격 증명 수정 폼은 표시하지 않는다. 실제 공급자에는 연결하지 않는다. 아래 실제 연결 흐름은 **실제 모드**에서 그대로 쓴다.

- **Google OAuth 온보딩**(google-play·google-ads·admob): `연결 이름`, `계정/조직 식별자`, `클라이언트 ID`(필수), `클라이언트 시크릿`(선택), 공급자 필수 온보딩 필드(예: packageName)만 입력한다. **갱신 토큰·서비스 계정 키는 입력하지 않는다** — 시스템 브라우저에서 Google 로그인(`accounts.google.com`)을 최초 1회 완료하면 서버의 loopback 콜백이 갱신 토큰을 암호화 저장하고 연결을 생성한다. 상태 폴링이 해당 연결 ID를 감지하면 창이 닫히고 `연결됨/미검증` 상태가 된다.
- **소셜(X · Threads) 브라우저 연결**: 앱 클라이언트 ID(및 시크릿; Threads는 필수, X는 선택)만 입력하면 시스템 브라우저에서 해당 공급자 로그인(x.com / threads.com)이 한 번 열리고, 서버가 토큰을 안전하게 저장해 연결을 만든다. 계정 식별자는 비워두면 로그인 후 자동으로 채운다. 정상 갱신에는 다시 로그인하지 않는다. 수동 토큰 등록도 가능하며 기존 비밀은 다시 표시하지 않는다.
- **수동 · 서비스 계정 입력**: OAuth를 쓰지 않는 공급자, 또는 서비스 계정/키 기반 연결에 사용한다. capability가 정의한 자격 증명 필드를 입력한다.
- 입력한 비밀 값은 보관함에 암호화되어 저장되고 화면에 다시 표시되지 않는다. 안전한 OS 보관함이 없으면 연결을 저장하지 않는다.
- **다시 연결**: Google 연결이 `사용자 조치 필요`/`권한 부족`일 때만 노출한다. 저장된 클라이언트 설정을 재사용해 재인증하며, 클라이언트 ID·시크릿을 다시 입력하지 않는다. 정상 상태에서는 재로그인을 요구하지 않는다.
- **자격 증명 수정**: 취소·만료된 키만 새로 입력해 서버에서 병합한다. 저장된 기존 값은 노출하지 않으며, 비운 항목은 변경하지 않는다.
- **상태 검사 / 연결 해제**: 검사는 권한·상태를 재확인한다. 해제는 관련 작업을 정지하고 보관된 자격 증명을 삭제한다.

> 실계정 미검증: Google 로그인·콜백·토큰 저장·갱신은 구현 및 모의 HTTP 검사를 완료했다. 사용자 실계정의 OAuth 권한·갱신 유지 검증은 남아 있다.

### 스토어 배포
- **출시 시작(공통 파이프라인)**: 프로젝트·타깃·스토어 연결·트랙/버전/출시 노트·빌드 옵션(구성·Godot 프리셋·iOS scheme)을 지정하면 `POST /projects/:id/publish`로 파이프라인을 시작한다. 서버가 검수 결과를 이벤트로 기록하고 빌드·업로드 두 작업을 파이프라인에 연결해 진행 상태를 관리한다. 프로젝트 상세의 **출시** 버튼에서도 같은 흐름을 연다(출시 후 배포 화면으로 이동).
- **파이프라인 드릴다운**: 배포·대시보드의 파이프라인 목록에서 각 출시의 상태(빌드 중·업로드 중·완료·실패·사용자 조치·취소)를 보고, 펼치면 빌드·업로드 작업의 로그·상태를 확인한다. `AppState.pipelines`(ReleasePipeline[])로 조회한다.
- 실제 운영은 저장된 권한·정책과 검증된 빌드만 사용한다. 업로드 성공이 곧 공개·심사 통과를 뜻하지 않는다.
- `빌드 업로드`(개별 작업)는 **선택한 프로젝트에서 성공한 빌드만** 후보로 노출하고 시험 트랙/브랜치(`track`, 기본 `internal`)로 업로드한다. 임의 경로 업로드는 없다. 빌드를 선택하면 그 소스 프로젝트의 앱 식별자를 표시하고, 이 스토어 연결의 앱과 일치해야 함을 경고로 안내한다. 서버가 업로드 시 앱 번들 식별자를 대조하며 다른 프로젝트의 빌드는 거부한다.
- 스토어 출시 리소스는 행을 펼쳐 메타데이터(버전·트랙·심사 상태 등, 날짜는 읽기 쉬운 형식)를 확인한다. 공급자가 광고한 작업(심사 제출·자료 수정 등)은 화면 설정에 없어도 연결 카드에서 모두 접근할 수 있으며, 공급자 필수 입력은 `operationFields`로 폼에 구성된다.
- 업로드 성공, 심사 접수, 실제 공개는 서로 다른 상태로 구분해 표시한다.

### 마케팅
- 캠페인 조회·생성·수정·중지. 캠페인의 모든 외부 변경은 대상 프로젝트를 먼저 선택해야 실행할 수 있다. 목록 행에서 시작하는 수정·중지는 해당 리소스의 프로젝트가 자동 선택되고(소유 프로젝트를 모르면 사용자가 직접 선택), 서버가 실제 소유권을 대조한다.
- 예산 변경은 프로젝트 정책 일일 한도 안에서만 허용하며, 초과 시 사전 차단한다.
- 성과 데이터가 지연될 때 자동 증액을 판단하지 않는다.
- 소재(creative)는 조회·생성·수정·활성화 작업을 공급자가 광고하면 노출한다. 캠페인·소재처럼 종류별 행 작업은 해당 리소스 종류에만 표시한다.
- 공급자가 광고한 작업은 화면 설정에 없어도 연결 카드에서 모두 접근할 수 있다(새로 추가된 미지의 작업 포함). 공급자 필수 입력은 capability `operationFields`로 폼에 구성된다. 라벨이 없는 미지의 작업 슬러그는 사람이 읽기 쉬운 형태로 자동 변환해 표시한다(원본 슬러그를 그대로 노출하지 않음). 마케팅·수익화·커뮤니티 화면 모두 이 원칙을 따른다.

### 수익화
- 광고 단위·상품 조회/생성/수정. 상품 생성은 Google Play·App Store 공통 필드를 사용한다. 광고 단위·상품의 모든 외부 변경도 대상 프로젝트 선택이 필수이며(행 작업은 리소스의 프로젝트를 자동 선택), 서버가 소유권을 대조한다.
  - 유형이 **구독**이면 결제 주기(`P1W`/`P1M`/`P3M`/`P6M`/`P1Y`)를 명시적으로 선택한다.
  - `설명`·`언어`·`기준 국가`는 선택 입력이며, 비우면 서버 기본값(언어 `en-US`, 국가 `US`)으로 등록됨을 폼에 표시한다.
  - 상품 수정 시 가격을 변경하면 통화를 함께 전송한다.
- 어댑터가 지원하지 않는 활성화·가격 변경은 만들지 않는다. capability의 지원 제한은 작업 폼과 환경 화면에 표시한다.
- 공급자·작업별 필수 입력이 다른 경우(예: Apple App Store, Google Ads 마케팅) 제어 서비스가 capability의 `operationFields`로 재정의를 보내면 작업 폼이 공통 스키마 위에 해당 공급자의 필수 필드를 덮어써 표시한다. 이 재정의가 없으면 공통 스키마를 그대로 사용한다.
- 수익 집계는 통화별로 분리 표시하고 추정치 포함 여부만 구분한다(정산·확정 여부를 임의로 단정하지 않음). 제어 서비스가 보내는 통화별 집계 주의(`MetricsSummary.warnings`)가 있으면 해당 통화 합계 아래에 표시한다. 미수집 값은 0이 아니라 미수집으로 표시한다.
- **일별 수익·광고비**: `AppState.metricFacts`(원천 팩트)를 날짜·통화별로 집계해 일별 막대 차트와 표를 보여준다. 접근성상 **표가 원본 데이터**이며(막대 SVG는 시각 보조), 통화가 여럿이면 통화 선택기로 전환한다. 통화가 다른 값은 합산하지 않는다.

### 커뮤니티
X · Threads · Steam 채널을 한곳에서 관리한다. 지원되는 작업만 노출한다(Steam 뉴스는 읽기 전용이며 자동 게시하지 않는다).

- 상단에서 프로젝트를 선택한다(게시물·예약·정책은 프로젝트에 연결된다). 연결된 커뮤니티 채널이 없으면 계정 연결로 안내한다.
- 채널별로 지원 조회 작업(게시물/멘션/답글/뉴스 조회)을 실행하고, 가져온 항목의 본문·지표·원문 링크를 보고, 게시물/멘션에 답글을 달 수 있다. 게시물 작성은 지원 채널에서만 노출한다.
- 게시물·답글은 실제 계정에 바로 반영되며 되돌릴 수 없다. 외부 쓰기는 사용자 작업 단위 멱등 키로 응답 유실 시 중복 게시를 방지한다.
- **예약 게시**: 내용·게시 시각(미래)·채널을 지정하면 제어 서비스가 지정 시각에 게시한다. 대기 중인 예약만 취소할 수 있다.
- **커뮤니티 자동화 정책**(프로젝트별, 1회 위임): 자동화 on/off, 대상 채널, 일일 게시 한도, 출시 자동 공지와 템플릿(치환자 `{projectName}`·`{version}`·`{platform}`), 규칙 기반 자동 답글을 저장한다. 저장한 범위 안에서는 매번 확인을 요청하지 않는다. 자동 답글 규칙은 입력한 문구와 일치할 때 저장된 응답만 보내며, 외부 내용을 명령으로 실행하지 않는다.

### 운영·복구
운영 준비 상태를 `GET /operations`(OperationsState)로 읽고, 변경은 각 운영 API로 위임한다. 서버가 저장·검증·이력을 기록하며 화면은 지원 여부를 근거 없이 성공으로 표시하지 않는다.

- **준비 상태**: 플랫폼 준비 항목(준비됨/조치 필요/사용 불가)과 상세, 안내 링크(`destination`)를 보여준다.
- **빌드 러너**: 러너 등록(`POST /operations/runners`, 이름·플랫폼·엔드포인트), 연결 검사(`.../:id/check`), 삭제(`DELETE .../:id`). 실제 모드에서는 **1회용 결합 토큰(pairingToken)** 을 반드시 입력한다(등록 시 한 번만 사용, 저장·표시 안 함). 데모에서는 결합 토큰을 받지 않는다(데모 합성 결합). 등록만으로 준비됨으로 표시하지 않고 프로토콜·도구 검사를 수행한다. 현재 실제 빌드 검증은 Linux Godot이며 macOS/Windows 내장 격리 실행은 후속 범위다.
- **운영 설정**: 보존 기간(일)·자동 백업·백업 시각(0–23)·알림을 `PUT /operations/settings`로 저장한다. 응답은 `OperationsSettings`이며, 저장 후 전체 운영 상태를 다시 읽는다.
- **백업·복원(설정)**: `POST /operations/backup`로 생성, `POST /operations/restore {backupId}`로 복원한다. 백업은 **프로젝트·정책·운영 설정**의 논리 백업이며, **계정 키(자격 증명)와 작업·외부 효과 작업 이력(ledger)은 보존**하고 되돌리지 않는다. 복원 응답(`restored`·`projectCount`·`automationsPaused`)을 표시한다 — 복원된 프로젝트 수와, 안전을 위해 일시중지된 자동화 수를 알려주며, 자동화는 검토 후 다시 활성화한다.
- **전체 백업(암호화 아카이브)**: 위 설정 백업과 **별개**의 카드다. 프로젝트·정책·설정에 더해 **계정 자격 증명·빌드 산출물·작업 이력**까지 하나의 **암호로 보호되는 이식 가능한 아카이브**(파일 매직 `APPOPSB1`)로 담아, 다른 기기 이전이나 전체 복구에 쓴다. 상태는 `GET /operations/portable-backups`(`PortableBackupState`)에서 폴링한다.
  - **암호**: 생성·복원 준비 시 **작업마다 입력**한다(12–1024자). 요청 직후 입력란을 비우며, **저장·로그·오류 표시에 남기지 않는다**(로그 마스킹에 `passphrase` 포함). 암호를 잃으면 복호화할 수 없고, 다른 곳의 비밀번호를 재사용하지 않는다.
  - **생성·진행·실패**: `POST /operations/portable-backups {passphrase}`가 `creating`으로 시작하고 목록에서 진행/실패/재시도(새 생성)를 보여 준다. 준비된 백업은 크기·파일 수·자격 증명 수를 표시한다.
  - **내보내기·가져오기(대용량 스트리밍)**: 데스크톱에서는 **main만** loopback+bearer로 스트리밍한다 — renderer는 파일 바이트·경로·토큰을 만지지 않는다.
    - **내보내기(다운로드)**: **`Content-Length`와 `X-AppOps-SHA256`을 모두 필수로 요구**하고(없으면 저장 거부, 과거 fail-open 제거), 응답을 목적지와 같은 디렉터리의 **배타적 임시 파일(`O_CREAT|O_EXCL|O_WRONLY`, 0600)**에 스트리밍하며 정확한 바이트를 해싱한다. 선언 길이·SHA-256과 정확히 일치할 때만 **파일과 부모 디렉터리를 `fsync`**한 뒤 **원자적 `rename`**으로 목적지를 교체한다(검증 전 기존 파일 미덮어쓰기, 실패 시 임시 파일만 제거하고 **기존 목적지 보존**).
    - **가져오기(업로드)**: 고른 **일반 파일을 `O_NOFOLLOW`로 단 한 번** 열어(심볼릭 링크 거부) 그 **하나의 디스크립터로 stat·매직(`APPOPSB1`)·업로드 스트림을 모두** 수행한다(검증 이후 경로 교체가 다른 파일을 올리지 못하도록 열린 inode에 고정 — TOCTOU 방지). 정확한 길이/상한을 강제하고 **정확한 `Content-Length`로** 업로드하며 결과는 `{id,size}`만 반환한다. 식별자는 엄격한 UUID로 제한하고 상한은 **512 GiB**다.
    - **브라우저 폴백(데모·미리보기)**: 인증 세션으로 파일 입력·다운로드를 제공하되 **메모리 상한(128 MiB)**을 둔다. 다운로드는 저장(트리거) 전에 데스크톱과 **동등하게 선언 길이·SHA-256·매직을 검증**하고(하나라도 누락/불일치면 저장하지 않음), 초과 시 데스크톱 앱 사용을 안내한다(죽은 버튼 없음).
  - **복원(명시적 덮어쓰기)**: `POST …/{id}/prepare-restore {passphrase}`가 `preparing`으로 시작해 준비되면 복원 요약(프로젝트/파일/자격 증명 수)을 보여 준다. **덮어쓰기 전** 별도의 명시적 버튼을 눌러야 `POST …/commit-restore {restoreId}`가 실행된다. 복원 시 현재 데이터를 덮어쓰며, **프로젝트는 다시 연결(relink)이 필요**할 수 있고, 복원된 **자동화는 일시중지** 상태로 시작하며, **계정 자격 증명은 보존**된다. 실제 모드는 `restartRequired:true`를 돌려주고 화면이 **명시적으로 제어 서비스를 다시 시작**(IPC)해 복원 데이터를 적재하며, 같은 복원 ID가 `committed`일 때만 완료로 확정한다. **데모는 격리 저장공간에만 복원하고 `restartRequired:false`를 돌려주되, 완료 확정은 `restored:true`가 있을 때만** 한다(그 신호가 없으면 완료로 표시하지 않고 재시도를 안내) — 실제 서비스는 절대 재시작하지 않는다. 모든 모드가 같은 화면을 쓰며 모드에 따라 `/api` 또는 `/api/demo`로만 라우팅된다.
- **진단**: `POST /operations/diagnostics`로 비밀이 제거된 진단 묶음을 생성해 요약·점검 항목·원본을 표시하고, 내용을 JSON 파일로 내려받는다(로컬 앱, 외부 업로드 없음).
- 데모에서는 러너·백업·진단이 데모 저장공간에서 동작하며 실제 기기·자원에 영향을 주지 않는다.

### 이력
- 작업(Run)과 타임라인을 한 곳에서 조회한다. 각 작업의 로그·상태·시도 횟수를 확인한다.
- 이력은 최신 항목부터 100개씩 불러온다. 탭·상태·프로젝트 필터를 바꾸면 진행 중이던 “더 보기” 응답이 새 목록에 섞이지 않도록 이전 요청을 무효화한다.
- 작업 로그(과거 페이지 포함)나 이전 이력을 불러오다 실패하면 빈 목록처럼 보이지 않게 오류를 그대로 표시한다.
- **상태 재확인(reconcile)**: 외부 처리 대기/사용자 조치 필요 상태의 **외부 쓰기** 작업에만 노출한다. 외부 공급자의 실제 반영 상태를 다시 읽을 뿐 쓰기를 재전송하지 않는다. 결과가 모호한 외부 쓰기는 일반 재시도를 제공하지 않는다. 서버가 재조정 미지원을 알리면 그 오류를 그대로 표시한다.

### 빌드 서명·SSH 키 (환경·정책 → 빌드 서명·SSH 키)

빌드에 필요한 두 종류의 비밀을 한 번 등록해 여러 프로젝트·빌드에서 재사용한다. 매번 로그인·키 입력을 요구하지 않는다.

- **SSH 키**는 사설 저장소·유료 애드온 같은 비공개 빌드 의존성을 빌드 **전에** 안전하게 내려받을 때 쓴다. 입력: 호스트(필수), 포트(선택, 기본 22), 사용자(선택, 기본 `git`), 비공개 키(파일 또는 텍스트, 필수), 패스프레이즈(선택), 고정 `known_hosts`(필수, 중간자 공격 방지용 호스트 키 핀). 
- **Android 키스토어**는 빌드 **후** 결과물(AAB/APK) 서명에 쓴다. 입력: 키스토어 파일(필수), 키스토어 암호(필수), 키 별칭(필수), 키 암호(선택, 비우면 키스토어 암호 사용).
- 파일 입력은 1MiB 이하만 허용하고 외부로 업로드하지 않는다. 파일 바이트는 로컬 제어 서비스 API로만 전송한다(키스토어는 base64, 키·known_hosts는 텍스트).
- 등록/회전(수정)/삭제를 제공한다. 회전은 입력한 항목만 교체하며 버전이 올라간다. 삭제는 프로젝트 빌드 보안에서 사용 중이면 서버가 거부한다.
- 화면과 응답에는 **메타데이터(지문·공개키·버전·호스트·키 별칭)만** 표시하고 비밀 값은 저장 후 다시 보여주지 않는다. 비밀은 안전 보관함에 저장되며 빌드 스크립트·스냅샷·로그에 남지 않는다(서버가 처리).
- 서버가 빌드 도구·SSH·서명 도구 부재를 알리면 그 오류를 그대로 표시한다. 실제 의존성 가져오기와 서명은 제어 서비스가 수행한다.
- **데모 키**: 데모 모드에서는 등록·회전 폼이 **라벨+종류만** 받고 실제 비밀(비공개 키·키스토어·암호)을 받지 않는다. 제어 서비스가 합성 자격 증명을 만들어 등록·회전·프로젝트 바인딩·사용 중 삭제 보호 등 흐름을 실제와 동일하게 보여준다. 생성된 데모 키도 같은 카드에서 지문·버전 등 메타데이터로 점검할 수 있다. 실제 모드의 키 폼은 그대로 정식 비밀 입력을 요구한다.

## 보안 경계

- renderer는 `window.appOps`만 통해 제어 서비스에 접근한다. Node 통합·webview·원격 모듈은 비활성이며 contextIsolation·sandbox를 사용한다.
- bearer 토큰은 main 프로세스에서만 `controller.json`에서 읽어 붙인다. 화면·로그·payload에 노출하지 않는다. backend 주소는 127.0.0.1로 고정하며, `APPOPS_API_URL`은 loopback일 때만 허용한다.
- Electron 창은 컴파일된 파일(`file:`) 또는 loopback dev 서버만 로드한다. `APPOPS_DEV_SERVER_URL`이 loopback(127.0.0.1/localhost/::1)이 아니면 무시하고 컴파일된 화면을 로드하며, 자격 증명 포함 URL도 거부한다. 외부 페이지로의 이동·새 창 열기는 차단한다.
- **IPC 발신자 신원(엄격)**: IPC는 (1) 우리가 만든 창의 **정확한 `webContents` 신원**과 (2) **최상위 신뢰 프레임 URL**을 모두 요구한다. 프레임 URL은 프로덕션에서 **패키지된 진입 파일의 정확한 `file:` URL만** 통과하며(임의의 `file://`이 아니다), 개발에서는 loopback dev 서버(프로토콜·호스트 일치)만 통과한다. 다른 `webContents`·서브프레임·다른 파일 URL은 거부한다.
- IPC 요청은 method+정규화 경로 화이트리스트를 통과해야 하고, 위 신뢰 발신자에서만 허용한다. 빌드 키 경로(`POST /build-credentials`, `PUT/DELETE /build-credentials/:id`, `PUT /projects/:id/build-security`)만 추가로 허용하며, 비밀을 되돌려주는 조회 경로(`GET /build-credentials/:id` 등)는 화이트리스트에 없다.
- **실행 모드 권한(main 소유)**: 실행 모드(demo/live)는 main이 소유·영속(`desktop-mode.json`, 0600, 기본 demo)한다. 특권 변경·파일 브리지·일반 요청은 이 모드에 결속되어 네임스페이스가 어긋나면 거부한다(`mode_mismatch`). 실제(live) 전환은 main 소유의 단 하나의 확인창을 통과해야만 반영된다(renderer 문자열로 권한을 바꿀 수 없다).
- 빌드 키·키스토어의 비밀은 로컬 제어 서비스 API로만 전송하고 외부로 업로드하지 않는다. 파일 입력은 1MiB로 제한한다. 화면·로그에는 비밀을 표시하지 않고 메타데이터만 노출한다.
- 커뮤니티 경로(`PUT /projects/:id/social-policy`, `POST /social/schedules`, `DELETE /social/schedules/:id`, 소셜 OAuth 시작 `POST /oauth/social/x|threads/start`, `POST /connections/:id/oauth/social/start`)만 추가로 허용한다. 소셜 OAuth 동의 화면은 `x.com`·`threads.com`·`threads.net`만 시스템 브라우저로 연다(서브도메인 위조·비HTTPS 거부).
- `openExternal`은 HTTPS이며 허용된 호스트(공급자 콘솔·문서와 `accounts.google.com`)만 시스템 브라우저로 연다. 자격 증명 포함 URL·미허용 호스트·비HTTPS는 거부한다.
- 로그에 남기는 객체는 자격 증명으로 보이는 키를 마스킹한다.
- 모드 경로 분리: 데모 요청은 `/api/demo/...`, 실제 요청은 `/api/...`로 전송된다. 렌더러는 상태를 만들지 않고 모드에 따라 `/demo` 접두만 한 번 붙이며, 실제 라우팅·분리·저장공간과 Electron IPC 경로 화이트리스트(데모 접두 및 운영·출시·데모 제어 경로 포함)는 제어 서비스·메인(루트)이 소유한다.

## 검증 결과

- 네이티브 실행 모드 권한 + 전송 하드닝(2026-09-12, Opus, D2 및 네이티브/브라우저 한계 반영): 실행 모드 권한을 renderer `localStorage`에서 **main 소유 상태(`desktop-mode.json`, 0600, 기본 demo)**로 옮겼다. 모든 특권 변경·파일 브리지·일반 요청 라우팅을 main 소유 모드에 결속해 **네임스페이스 불일치를 거부**(`mode_mismatch`)하고, 실제(live) 전환은 **main 소유의 단 하나의 확인창**(renderer 확인창 대체 — 이중 프롬프트·재로그인 없음)을, 데모 전환은 추가 확인 없이 처리한다. `getMode`/`setMode` 브리지를 노출하고, 네이티브는 데이터 디스패치 전에 **권위 있는 비동기 부트스트랩**으로 모드를 확정하며 전환/재로드에서 불변 모드-클라이언트 계약을 유지한다. IPC는 **정확한 패키지 진입 URL + 알려진 `webContents` 신원**을 요구한다(임의 `file://` 아님). 다운로드는 **`Content-Length`+SHA-256 필수 → `O_EXCL` 0600 임시 파일 스트리밍 → 정확 바이트 해싱 → 파일+부모 `fsync` → 성공 시에만 원자적 교체**, 가져오기는 **`O_NOFOLLOW` 단일 디스크립터**로 stat·매직·스트림을 모두 수행(경로 스왑 방지)하고 `{id,size}`만 반환한다. 브라우저 폴백 다운로드는 저장 전 길이·SHA-256·매직을 검증하고, 데모 복원 완료는 `restored:true`일 때만 확정한다. `PortableBackupPanel`의 불필요한 채팅 비밀번호 문구를 제거했다. **행위 테스트**: `tests/desktop-mode.test.ts`(네임스페이스 결속·경로 스왑·저장 모드 정규화·정확 진입 URL·다운로드 헤더 필수) 신설, `tests/desktop-backup-bridge.test.ts`에 원자적 교체·실패 시 원본 보존·`O_NOFOLLOW` inode 고정(경로 스왑)·심볼릭 링크 거부·SHA 판정 추가. `desktop-security`+`desktop-backup-bridge`+`desktop-mode` 41/41, 인접 스위트(+`portable-backup`·`portable-backup-controller`·`demo-workflows`) 62/62 통과. `apps/desktop/**` 오류 0(`tsc --noEmit`). 이 작업은 소스만 수정했고 루트의 진행 중 네이티브 dist 테스트를 방해하지 않도록 **재빌드·재실행은 하지 않았다**. 실 데스크톱 창 종단·세 OS는 여전히 미검증이다.

- 패키지 Electron 네이티브 창 스모크(이 환경 제한, `--no-sandbox` 미사용): 컴파일된 main→컨트롤러 기동 경로는 `ELECTRON_RUN_AS_NODE=1`로 검증했으나 Chromium 창 실행은 이 호스트의 샌드박스 제약으로 막혀 있다. 원인 (1) Electron 번들 `node_modules/electron/dist/chrome-sandbox`가 setuid root(4755)가 아니고, (2) `kernel.apparmor_restrict_unprivileged_userns=1`로 비특권 user namespace 샌드박스가 차단되며(따라서 `--disable-setuid-sandbox`도 “No usable sandbox”로 실패), (3) 무암호 sudo 불가로 위 두 항목을 고칠 수 없다. 시스템에 설치된 setuid-root `/opt/google/chrome/chrome-sandbox`(`-rwsr-xr-x root:root`)를 찾아 `CHROME_DEVEL_SANDBOX`로 지정해 실행을 시도했으나 이 Electron 빌드는 해당 환경변수를 무시하고 여전히 자신의 번들 `chrome-sandbox`(4755 아님)를 요구하며 즉시 종료했다. 해결에는 관리자 권한으로 번들 `chrome-sandbox`를 root 소유 4755로 설정하거나 AppArmor userns 정책(`kernel.apparmor_restrict_unprivileged_userns=0` 또는 프로파일)을 조정해야 한다. `DISPLAY`가 있어 문제는 디스플레이가 아니라 샌드박스이므로 Xvfb는 불필요하다. 네이티브 창이 동작한다고 주장하지 않으며, 실 데스크톱 창 종단 QA는 이 선행 조건 해결 후 수행한다.
